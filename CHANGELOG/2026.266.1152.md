# 2026.266.1152 — feat: add the check-charly-debian-repo R10 bed for the published package repo

## Summary of changes

Relocate the `check-debian-repo` R10 check bed (and the `debian-repo-vm` template it deploys) into `opencharly/charly-debian`, the repo that OWNS the published apt artifact the bed tests.

WHY: a check bed must live in the repo that owns what it tests. The check-bed runner's dev-tree override (`proc.SelfSuperprojectOverridePair`, `spec/proc/repo_override.go`) points the bed PROJECT's own superproject's `@github` refs at the local tree. In this umbrella every submodule's superproject is `opencharly/opencharly` (which hosts no candies), so a candy owned by another repo was never exercised as in-development code while its bed sat in `charly`. Relocated here, the bed composes the LOCAL candy with no `@github` pin.

**Changed files:**
- `charly.yml` — adds `debian-repo-vm` (disposable Debian 13 trixie cloud-image VM, `backend: libvirt`, `base_user: debian`, explicit `distro: debian`) and the `check-debian-repo` bed (7 deterministic `check:` steps: key tooling → GPG key dearmored into `/etc/apt/keyrings` → apt repo added → `apt-get update` resolves the repo → `apt-get install charly` → installed binary version equals the dpkg-recorded version → welded command plugins dispatch project-less from `/tmp`). Also `defaults` (platform/tag/registry/build/merge).
- `.gitignore` — new file: the standard generated-artifact rules (`.build/`, `.check/`, `.containerignore`, `.dockerignore`, `output/`, `*.swp`, `*~`, `*.bak`, `*.bak.*`).
